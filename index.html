Las tres ramas

main

Lo que se entrega. Siempre estable.

Nunca se sube código directo. Solo recibe merges desde dev.

dev

Donde se junta y se prueba todo.

Recibe cada HU terminada. Cuando todo funciona, pasa a main.

huN

Una rama por cada historia de usuario.

Sale de dev y vuelve a dev al terminar.

Pasos para cada HU

  1. Partir de dev actualizado
    git checkout dev
git pull
  2. Crear la rama de la HU (mismo nombre en código y docs)
    git checkout -b hu4
  3. Trabajar y hacer commits con el número de la HU
    git commit -m "HU-04: modo edición de una tarea"
  4. Terminada y probada la HU, un solo PR a dev (CI en verde)
    git push -u origin hu4
gh pr create --base dev --head hu4 --title "HU-04: Editar una tarea"
gh pr merge --merge
  5. Solo en una entrega a producción: PR de dev a main
    gh pr create --base main --head dev --title "Release: v1.0"
gh pr merge --merge
Regla de oro: nunca se hace commit directo en main. Si estás en main, cambia a dev o a tu rama de HU antes de trabajar.
